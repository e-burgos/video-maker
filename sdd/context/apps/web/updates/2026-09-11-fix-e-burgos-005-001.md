# FIX-e-burgos-005-001 — 2026-09-11

## Estado
La biblioteca deja de ser sólo de lectura: cada tarjeta de asset tiene un **Delete** con confirmación
por nombre de archivo. Si la API contesta `409 ASSET_IN_USE`, la misma confirmación pasa a mostrar los
usos que reportó el servicio y ofrece **Delete anyway** (reintento con `force`); al confirmar se recarga
el listado. Textos nuevos en los dos catálogos i18n (`assetDelete.*`, `error.ASSET_IN_USE`,
`error.ASSET_NOT_FOUND`). Suite: 90 archivos / 876 tests, 99,27 % stmts · 95,68 % branch (piso 80 %).

## Estructura
- `components/asset-delete-control.tsx`: la máquina de tres pasos (`closed` → `confirm` → `in-use`).
  Vive aparte de `AssetCard` porque es lo único de la tarjeta que habla con el cliente; `AssetCard`
  pasó a recibir `onDeleted` y a etiquetarse con `data-testid="asset-card"` + `data-asset-path`, que es
  cómo el E2E ubica una tarjeta concreta.
- `api/asset-path.ts` → `assetFileName(path)`: el segmento que viaja como `:filename` del DELETE.
- `api/render-api-client.ts` → `deleteAsset({ slug, role, filename, force })`, con `?force=true` sólo
  cuando `force`. Tipos `AssetDeletion`/`TimelineAssetReference` **derivados de `sdd/api.json`** (D-5),
  no importados de la API.
- `api/error-explanations.ts` explica `ASSET_IN_USE` y `ASSET_NOT_FOUND`, así que el `ErrorNotice`
  muestra la explicación traducida además del código.
- `e2e/delete-asset-smoke.mjs` (puertos 4420/4421, media root temporal copiado de `media/smoke-ingest`):
  sube un archivo por el uploader, lo borra desde la UI y verifica disco y catálogo; después intenta
  borrar el A-roll que usa la timeline, ve el aviso y lo borra con **Delete anyway**.

## Dependencias
Ninguna npm nueva.

## Qué sigue
- La confirmación es inline en la tarjeta, no un modal: con muchos usos de timeline la tarjeta crece
  bastante (ver `artifacts/delete-asset-04-in-use.png`).
- No hay borrado múltiple ni deshacer. Un borrado con `force` rompe la timeline y la UI sólo avisa.
