# FIX-e-burgos-015-001 — 2026-09-10

## Estado
El modelo del productor ya no lo congela el arranque del servicio: `POST /projects/:slug/producer/messages`
acepta `model?`, lo valida contra la lista permitida (`422 PRODUCER_MODEL_INVALID`), lo pasa a
`claude --model` y lo persiste en `session.json`. `GET …/producer` publica
`models: { default, allowed: [{ id, label, description }] }`, el turno informa `model` y cada mensaje del
asistente queda guardado con el modelo que lo escribió. Sin `model` en el body, el turno sigue con el de la
sesión y cae a `PRODUCER_MODEL`.

## Estructura
`ProducerConfig` gana `models` y `describeProducerModel(id)` (label/description por alias, fallback al id).
`producerCliArgs(start)` ya no recibe la config: el modelo viaja en `ProducerTurnStart`, y
`ProducerTurnRecord` lo guarda (`registry.reserve(slug, turnId, startedAt, model)`).

## Dependencias
Variable nueva `PRODUCER_MODELS` (default `sonnet,opus,haiku`); `PRODUCER_MODEL` debe pertenecer a la
lista o el arranque aborta con `SERVER_CONFIG_INVALID`. Código de error nuevo `PRODUCER_MODEL_INVALID` (422).
